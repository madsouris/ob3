# Fixtures

Curated, deterministic workspaces committed to the repo. **Nothing here is user data.** Real workspaces live outside this repository (usually a separate Git repo); the fixtures exist so tests are reproducible and so `ob init --demo` has a single source of truth to copy.

## Layout

```
fixtures/workspaces/
├── demo/            canonical demo workspace — seeded by `ob init --demo`,
│                    copied to dist/demo at build time, shipped in the package
└── external-edits/  every external-edit behaviour from docs/05:
                     rename, duplicate id, missing id, invalid YAML,
                     dangling refs, orphan task, conflict markers,
                     duplicate numbers, unknown keys
```

| Fixture | Committed | Purpose |
|---|---|---|
| `demo` | yes | seed data, preview, integration tests |
| `external-edits` | yes | the external-edit contract (`tests/index/*`) |
| `broken-config` | planned | invalid `.ob/config.json` |
| `large` | **no** — generated | 10k synthetic records for perf tests (`pnpm fixture:large`), gitignored |

Cases that cannot be committed sanely are generated inside tests instead: CRLF files, BOM files, files above 2 MB, symlinks (including escaping directory symlinks), and mid-save truncated YAML.

## Rules

1. **Never add a working workspace here.** If you want to try the app, use a scratch directory outside the repo (`~/.ob-scratch`) or the gitignored `/.scratch/`.
2. Fixtures are byte-stable: no absolute paths, no machine-specific timestamps, no user names. Tests compare exact content.
3. Record fixtures must satisfy the schemas in `docs/03-data-model.md` — `tests/workspace/demo-source.test.ts` and `tests/index/external-edits.test.ts` enforce this.
4. `.ob/config.json` belongs inside the fixture when the fixture is meant to be a complete workspace; `.gitignore` and empty directories are generated by the initializer, not stored here.
5. Adding a fixture means adding it to the table above and to the coverage in `docs/12-testing-and-verification.md`.
